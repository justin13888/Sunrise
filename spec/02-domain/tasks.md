# Task

The unit of intent.

## Fields

```cddl
Task = {
    id:            tstr .regexp "tsk_[A-Z0-9]{26}",
    created_at:    tdate,
    updated_at:    tdate,           ; CRDT-derived; max of contributing op times
    title:         text<512>,        ; required, 1..512 chars after trim
    body?:         NoteBody,          ; rich-text; see notes.md
    stream_id:     tstr,              ; "inbox" stream ID is the default
    contexts:      [+ tstr],          ; observed-remove set; may be empty
    state:         TaskState,
    priority?:     1..5,              ; 1 = highest, 5 = lowest; absent = unset
    energy?:       Energy,            ; "low" / "med" / "high"
    estimated_duration?: duration,    ; ISO 8601 duration
    scheduled_at?: tdate,             ; when user intends to do it
    due_at?:       tdate,             ; deadline; UI distinguishes from scheduled_at
    completed_at?: tdate,             ; set on transition to Done
    deferred_count: uint,             ; PN-counter; surfaced in review
    blocks:        [* tstr],          ; block IDs scheduling this task
    blocked_by:    [* tstr],          ; task IDs this depends on
    blocks_others: [* tstr],          ; reverse of blocked_by; derived; not synced
    assignee?:     tstr,              ; person ID; v1: informational only
    routine_id?:   tstr,              ; if generated by a routine
    routine_occurrence?: tdate,       ; occurrence date for routine-generated tasks
    archived:      bool,              ; default false
    deleted:       bool,              ; default false (tombstone)
}

TaskState = "todo" / "in_progress" / "blocked" / "done" / "cancelled"
Energy = "low" / "med" / "high"
```

Field-level rationale:

- `priority` is 1..5, not a free integer, to keep UI affordances finite.
- `energy` is a Sunrise-specific facet — multi-stream operators choose work by energy, not just priority.
- `estimated_duration` is mandatory for tasks that get auto-scheduled; optional otherwise.
- `deferred_count` is a counter the system increments; it is not user-editable.
- `blocks_others` is *not* persisted — derived from `blocked_by` reverse lookup.

## State machine

```
   ┌──────┐    start     ┌──────────────┐    finish    ┌──────┐
   │ todo │ ───────────▶ │ in_progress  │ ───────────▶ │ done │
   └──────┘              └──────────────┘              └──────┘
      │  ▲                     │                          ▲
      │  │ unblock              │ (blocked_by added)      │ resurrect
      │  │                      ▼                          │
      │  │              ┌────────────┐                    │
      │  └──────────────│  blocked   │────────────────────┘
      │                 └────────────┘
      │
      ▼
  ┌───────────┐
  │ cancelled │
  └───────────┘
```

- `done` and `cancelled` are *not* terminal: a task can transition back to `todo`. UI may warn but does not refuse.
- `blocked` is computed in v1: a task is `blocked` iff `blocked_by` is non-empty AND every blocker's state ≠ `done`/`cancelled`. The persisted `state` field is the user-set state; UI shows effective state.

## Lifecycle

- **Created** in Inbox by default unless captured into a specific stream.
- **Promoted** to a stream by drag, keyboard, or natural-language parsing (`#streamname` in capture).
- **Scheduled** by setting `scheduled_at` (and optionally a Block).
- **Completed** by user action; `completed_at` set; if part of a routine, the routine's streak counter advances.
- **Deferred** by changing `scheduled_at` to a later date; `deferred_count` increments by 1; UI exposes the running count to nudge the user toward "drop it or do it."
- **Archived** to remove from default views without deleting.
- **Deleted** sets `deleted=true`; remains as tombstone until compaction.

## Validation

- `title` MUST be non-empty after trim.
- `due_at` ≥ `scheduled_at` if both are set (UI may reorder if user inverts).
- `blocked_by` MUST NOT contain `id` (no self-blocking).
- `blocked_by` cycles are detected on submit and rejected (cycle = chain of blocked_by returning to start). The check is local; with concurrent edits, a cycle can transiently form across devices and will be broken by a deterministic tie-breaker on merge (see [`../05-sync/conflict-resolution.md`](../05-sync/conflict-resolution.md)).

## CRDT mapping

- Task is a CRDT map.
- Scalars: LWW-register on `(timestamp, device_id)`.
- `contexts`: observed-remove set.
- `blocks`, `blocked_by`: observed-remove sets.
- `deferred_count`: PN-counter.
- `body`: a CRDT text type (Loro RichText).
