# Internationalization

Amended by [ADR-0054](../11-adr/0054-string-catalog-pipeline.md): the generator, the message subset, the key surfaces, the plural matrix's template check, locale negotiation, and the documentation site.

## Current scope

- **UI strings:** English at launch. Locales prepared in code; we accept community translations after stabilization.
- **Date / time / number formatting:** locale-aware from day one (CLDR via ICU4X).
- **Time zones:** IANA database; routine and reminder evaluation always tz-aware.
- **Right-to-left:** layout supports RTL but no RTL locale is shipped.
- **Plurals:** CLDR plural rules; messages use ICU MessageFormat.

## String catalog

- Single source: `i18n/en.toml`. A translation is `i18n/<locale>.toml` holding any subset of its keys, with the same arguments of the same kinds; a key it omits falls back to English, formatted by English plural rules.
- One TOML key per UI string. No string concatenation; placeholders only via MessageFormat. Layout — indentation, bullets, a trailing colon before a list — stays in the code; the catalog holds words.
- The first key segment is the **surface** that shows the string, and decides which bindings carry it: `common` (all), `web` and `docs` (TypeScript), `apple` (Swift), `cli` (Rust). Key segments are snake_case with every `_` followed by a letter.
- Generated bindings into TypeScript (`messages.ts`), Swift (`Strings.swift`, typed `L10n` accessors, over `Localizable.xcstrings`, a String Catalog Foundation formats), and Rust (`strings.rs`, `include!`d by the CLI over an ICU4X runtime), by `packages/sunrise-i18n` ([ADR-0054](../11-adr/0054-string-catalog-pipeline.md)). They are committed and drift-gated (`mise run i18n-check`, CI `i18n-current`), because Xcode and `cargo build` cannot run the generator. Kotlin is emitted with the Android client.
- A comment above a key is the translator's context.

### Message subset

Values are ICU MessageFormat restricted to what every binding renders identically:

- text, `{name}` (a string), `{name, number}` (an integer in the locale's digits);
- `{name, plural, …}` over an integer, with CLDR category arms, an optional `=0` arm, and `#` for the formatted count.

`select`, `selectordinal`, `date`, `time`, number styles and skeletons, `offset:`, exact arms other than `=0`, and a plural nested in a plural arm are refused at build time: a String Catalog has no equivalent, and a message must not render differently per client. Format a date with the platform's date API and pass it as a string. `=0` is refused in a locale whose CLDR rules have a `zero` category; write the `zero` arm there. Argument names are snake_case and become identifiers in every binding.

Only prose a person reads is a message. CLI output a script reads — a record per line, an id, JSON — is not.

### Plural-rule test coverage

- The CI plural-coverage matrix (`i18n-plurals`, `mise run i18n-plurals <locale>`) runs three locales that span the CLDR plural-rule shape space:
  - **en** — `one / other`
  - **pl** — `one / few / many / other`
  - **ar** — `zero / one / two / few / many / other`
- For every TOML string in the catalog, CI parses the value and asserts that ICU MessageFormat compiles cleanly under each of the three locales. A missing plural arm is a build failure, and so is a dead one (a category the locale never selects, such as English `zero`).
- A locale is checked against its own catalog where one exists. Where none does, it is checked against the template a translator into it starts from: every source message with its plurals reshaped to the locale's categories, seeded from `other`. English messages are never required to carry Polish or Arabic arms.
- Each message is also rendered, for every category an integer can reach, with that category's smallest sample, and must select that category's arm through the runtime the web bundle ships.
- Adding a new translated locale adds a CI matrix entry that runs the same parser against that locale's plural rules.

## Date / time presentation

- Today: "Friday, May 8" in user's locale.
- Times: localized 12h / 24h based on OS preference.
- Relative ("in 3 hours") for near future; absolute beyond a horizon.
- Time zones: respect OS-reported tz; allow per-Stream override (rare).

## Sorting / collation

- Use ICU collation for stream names, contexts, person display names.

## Search tokenization

- Sunrise ships a single FTS5 tokenizer: English `unicode61 + porter`. This is the default and the only configuration available.
- CJK text is handled by the trigram index of [ADR-0052](../11-adr/0052-search-v2.md), with the word index's stemmer following the vault's content language. Neither is built; search is ranked as [#345](https://github.com/justin13888/Sunrise/issues/345). Both indexes are device-local and never sync, so no capability bit is needed for them. Dictionary-based word breaking (Thai and similar scripts) is not planned; the trigram index finds substrings in those scripts instead.

## Right-to-left

- Layout system uses logical properties (start/end) not physical (left/right). On the web that is `paddingInline`, never `paddingLeft`; the client sets `<html lang dir>` from the negotiated catalog locale at load.
- Icons that imply direction (arrows) are mirrored automatically.
- Tested with pseudo-RTL builds.

## Locale negotiation

- **Web and docs site:** `navigator.languages` in preference order against the catalog's locales — an exact tag, then its language subtag, then English.
- **Apple apps:** Foundation's, from the String Catalog's localizations and the user's preferred languages.
- **CLI:** `LC_ALL`, then `LC_MESSAGES`, then `LANG` (an empty variable is skipped), with the POSIX spelling `pl_PL.UTF-8` read as `pl-PL`, then the same matching as the web.

## Documentation site and README

- The documentation site is `apps/docs`, VitePress over `docs/` unchanged ([ADR-0054](../11-adr/0054-string-catalog-pipeline.md) §6). Its own chrome (title, description, navigation) is the catalog's `docs` surface.
- A translated docs page lives at `docs/<locale>/…`, mirroring the English path, and the locale is added to the site's `locales`.
- A translated README is `README.<locale>.md` beside `README.md`, linked from the **Languages** line under its title.

## Localization workflow

- POEditor / Crowdin or self-hosted Weblate (not chosen). Until one is, a translation is a pull request adding `i18n/<locale>.toml`.
- Community translations vetted by a maintainer before shipping.
- Strings flagged as "in flux" are not released to translators until stable.

## Accessibility intersect

- Larger text scale must hold across locales (German strings can be ~30% longer than English).
- Right-to-left works with screen readers in their native idiom.

## What we explicitly defer

- Localized AI features (semantic capture parsing in non-English).
- Locale-specific recurrence ("first business day of month" with country calendars).
- Calendar systems other than Gregorian (Hijri, Hebrew, etc.).

## Numbers

- Stream counts, priority numbers — locale-aware digits.
- Avoid hardcoded "1 task" / "3 tasks"; use plural rules.
