# Internationalization

## Scope at v1

- **UI strings:** English at launch. Locales prepared in code; we accept community translations after stabilization.
- **Date / time / number formatting:** locale-aware from day one (CLDR via ICU4X).
- **Time zones:** IANA database; routine and reminder evaluation always tz-aware.
- **Right-to-left:** layout supports RTL but no RTL locale is shipped at v1.
- **Plurals:** CLDR plural rules; messages use ICU MessageFormat.

## String catalog

- Single source: `i18n/en.toml`.
- One TOML key per UI string. No string concatenation; placeholders only via MessageFormat.
- Generated bindings into Swift, Kotlin, and TS at build time.

### Plural-rule test coverage

- The CI plural-coverage matrix runs three locales that span the CLDR plural-rule shape space:
  - **en** — `one / other`
  - **pl** — `one / few / many / other`
  - **ar** — `zero / one / two / few / many / other`
- For every TOML string in the catalog, CI parses the value and asserts that ICU MessageFormat compiles cleanly under each of the three locales. A missing plural arm is a build failure.
- Adding a new translated locale adds a CI matrix entry that runs the same parser against that locale's plural rules.

## Date / time presentation

- Today: "Friday, May 8" in user's locale.
- Times: localized 12h / 24h based on OS preference.
- Relative ("in 3 hours") for near future; absolute beyond a horizon.
- Time zones: respect OS-reported tz; allow per-Stream override (rare).

## Sorting / collation

- Use ICU collation for stream names, contexts, person display names.

## Search tokenization

- v1 ships a single FTS5 tokenizer: English `unicode61 + porter`. This is the default and the only configuration available at v1.
- Locale-specific tokenizers (CJK, Thai, etc.) are deferred to a future version. There is no v1 capability bit for alternative tokenizers; when a future version introduces one, the negotiation rules in [`protocol-versioning.md`](./protocol-versioning.md) apply.

## Right-to-left

- Layout system uses logical properties (start/end) not physical (left/right).
- Icons that imply direction (arrows) are mirrored automatically.
- Tested with pseudo-RTL builds.

## Localization workflow

- POEditor / Crowdin or self-hosted Weblate (decision deferred).
- Community translations vetted by a maintainer before shipping.
- Strings flagged as "in flux" are not released to translators until stable.

## Accessibility intersect

- Larger text scale must hold across locales (German strings can be ~30% longer than English).
- Right-to-left works with screen readers in their native idiom.

## What we explicitly defer

- Localized AI features (semantic capture parsing in non-English).
- Locale-specific recurrence ("first business day of month" with country calendars).
- Calendar systems other than Gregorian (Hijri, Hebrew, etc.).

## Numbers

- Stream counts, priority numbers — locale-aware digits.
- Avoid hardcoded "1 task" / "3 tasks"; use plural rules.
