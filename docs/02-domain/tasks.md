# Task

The unit of intent.

> **Amended** by [ADR-0044](../11-adr/0044-per-field-ops.md) (per-field merge),
> [ADR-0046](../11-adr/0046-optional-stream.md) (optional stream, Inbox as a
> view) and [ADR-0047](../11-adr/0047-deadlines-and-lateness.md) (plan time,
> two deadlines, lateness and triage). Time rules are normative in
> [`../10-cross-cutting/time.md`](../10-cross-cutting/time.md). Where the tree
> has not caught up, the gap is named in §Status in the tree.

## Fields

Shared types (`entity-ref`, `timestamp`, `NoteBody`, `unknown-fields`, `text<N>`)
are defined once in [`overview.md` §Common CDDL types](./overview.md#common-cddl-types).
`stime` is the four-kind `SunriseTime` in
[`time.md` §1](../10-cross-cutting/time.md#1-every-stored-time-is-a-sunrisetime).

```cddl
Task = {
    id:            tstr .regexp "tsk_[0-9A-HJKMNP-TV-Z]{26}",
    created_at:    timestamp,
    updated_at:    timestamp,         ; merge-derived: the latest stamp of any field op
    title:         text<512>,         ; required, 1..512 chars after trim
    body?:         NoteBody,          ; opaque bytes; see notes.md
    stream_id?:    entity-ref,        ; str_ ref; absent = no stream (private key domain)
    contexts:      [* entity-ref],    ; ctx_ refs; OR-set; may be empty
    state:         TaskState,
    priority?:     1..5,              ; 1 = highest, 5 = lowest; absent = unset
    energy?:       Energy,            ; "low" / "med" / "high"
    estimated_duration_s?: uint,      ; SECONDS, not an ISO 8601 duration string
    planned_at?:   stime,             ; when I intend to work on it; the planner and defer own it
    target_at?:    stime,             ; soft deadline
    hard_due_at?:  stime,             ; hard deadline
    scheduling_constraints?: [* SchedulingConstraint], ; one register (max 16); see scheduling-constraints.md
    completed_at?: stime,             ; instant, or all_day for a backdated "done that day"
    cancel_reason?: text<512>,        ; meaningful only while state = cancelled
    deferred_count: int,              ; PN-counter; +1 per defer
    sort_order?:   tstr,              ; fractional index within the task's stream (or the no-stream set)
    triaged_at?:   timestamp,         ; explicit "looked at, belongs nowhere, no date"
    late_acknowledged_at?: timestamp, ; Keep in the triage queue
    blocks:        [* entity-ref],    ; blk_ refs: derived from block_tasks, read-only
    blocked_by:    [* entity-ref],    ; tsk_ refs: OR-set of tasks this depends on
    assignee?:     entity-ref,        ; prs_ ref; informational only
    routine_id?:   entity-ref,        ; rtn_ ref: the series root, if generated by a routine
    routine_occurrence_key?: occurrence-key, ; the civil occurrence key; see routines-and-recurrence.md
    reminder_lead_s?: uint,           ; seconds before planned_at; omitted when unset
    archived:      bool,              ; default false
    deleted:       bool,              ; default false (tombstone)
    unknown-fields,                   ; see overview.md
}

TaskState = "todo" / "in_progress" / "done" / "cancelled" / tstr   ; unknown values preserved
Energy    = "low" / "med" / "high" / tstr
```

Field-level rationale:

- **`stream_id` is optional.** A task with no stream belongs to no project and
  is sealed under the vault's private key domain, which is not a Stream and is
  never shared or listed ([ADR-0046](../11-adr/0046-optional-stream.md) §2).
  A reference to a deleted stream resolves through the tombstone's
  `rehomed_to`, so no reader ever sees a task in a deleted stream
  ([ADR-0046](../11-adr/0046-optional-stream.md) §4).
- **Three times, three owners.** `planned_at` is a plan, `target_at` is a
  goal, `hard_due_at` is a fact about the world. Defer and the planner write
  only `planned_at` ([ADR-0047](../11-adr/0047-deadlines-and-lateness.md) §1).
- `priority` is 1..5, not a free integer, to keep UI affordances finite.
- `energy` is a Sunrise-specific facet: multi-stream operators choose work by
  energy, not just priority.
- `estimated_duration_s` is seconds, not an ISO 8601 duration string. The
  string form would encode the same value many ways (`PT1H`, `PT60M`), and
  canonical CBOR cannot pick between them, so two devices writing "one hour"
  would produce different bytes and so different signatures. The planner
  places only tasks that have one.
- `deferred_count` is a PN-counter: each defer contributes `+1` from its
  device, so concurrent defers all count. It is not user-editable.
- `sort_order` is a fractional-index key using the same encoding as
  `Stream.sort_order` ([`streams.md` §Sort order](./streams.md#sort-order)).
  One order per task, within its stream or within the no-stream set. A reorder
  rewrites one key; ties break by id. The core computes keys
  (`MoveTasks { ids, before, after }`); clients never do. Tracked in [#340](https://github.com/justin13888/Sunrise/issues/340).
- **There is no `blocks_others` field, and no `blocked` state.** Both are
  derived at read time (see §State machine) and neither is persisted or
  serialized.
- `reminder_lead_s` is the top of the notification lead-time hierarchy
  (task → Stream → the `default_reminder_lead_s` preference). Absent means "not
  set here", which is what makes it a fallback chain; `0` is a real answer
  meaning "fire at the planned time".
- `scheduling_constraints` restricts when the task should be planned or done,
  and where. Full semantics in [`scheduling-constraints.md`](./scheduling-constraints.md).
- `assignee` is a single-valued, **informational** Person reference. It grants
  the assignee no access; it is a label. Delegation (multiple assignees,
  hand-off semantics) would be a separate field, not a re-typing of this one.

### What a command can and cannot set

The CDDL is the wire shape. Several fields are system-derived or written only
by one command. `TaskDraft`, `TaskPatch` and the commands below are the whole
user-facing write surface:

| Field | How it is written |
|---|---|
| `planned_at` | `TaskPatch`, `Command::Triage` with `Defer`, and a planner commit ([ADR-0048](../11-adr/0048-interactive-planner.md)). Always a whole `stime`; the kind given is the kind stored. |
| `target_at`, `hard_due_at` | `TaskPatch` only. No defer, triage action or planner commit writes them. |
| `completed_at` | Stamped *now* on a transition to `done`; set to a given past value by `Triage` with `AlreadyDone` (not after now, not before `created_at`); cleared on any transition out of `done`. |
| `cancel_reason` | `Triage` with `Drop`; cleared on any transition out of `cancelled`. |
| `deferred_count` | `+1` from each defer. No command resets it. |
| `triaged_at` | `MarkTriaged` sets it to now; `ReturnToInbox` clears it. |
| `late_acknowledged_at` | `Triage` with `Keep` sets it to now. |
| `sort_order` | `MoveTasks` only. |
| `blocks` | Derived read-only from the `block_tasks` index; see [`time-blocks.md`](./time-blocks.md) §Symmetry. |
| `routine_id` / `routine_occurrence_key` | Set only by routine materialization. No patch field in either direction. |
| `deleted` | `DeleteTask` sets it. A restore clears it, and a restore is how a delete is undone ([ADR-0044](../11-adr/0044-per-field-ops.md) §5). No other write resurrects a deleted task. |

Every multi-task action is **one** command over a selection
(`Command::Triage { ids, action }`, `MoveTasks`, `MarkTriaged`), validated
all-or-nothing and applied in one transaction, with per-task, per-field ops
([ADR-0047](../11-adr/0047-deadlines-and-lateness.md) §4).

## Inbox

The Inbox is a **view**, not a place a task lives:

```
inbox(task) = effective_stream(task) IS NULL
          AND planned_at IS NULL AND target_at IS NULL AND hard_due_at IS NULL
          AND triaged_at IS NULL
          AND state ∈ {todo, in_progress} AND NOT archived AND NOT deleted
```

A task leaves the Inbox by acquiring a stream, a time, or an explicit
`triaged_at`, and nothing has to clear a flag for that to happen
([ADR-0046](../11-adr/0046-optional-stream.md) §3).

## Lateness and triage

Lateness is derived in Rust at read time from the task's fields, `now`, the
reader's zone and the day schedule, and is never stored:

| State | When |
|---|---|
| `LateHard` | `hard_due_at` has been missed |
| `LateSoft` | `target_at` has been missed |
| `Stale` | no deadline, and untouched for `stale_after_days` planner days (default 14) |
| `OnTrack` | otherwise |

An `all_day` deadline is missed at the **end** of its planner day. A slipped
`planned_at` is not lateness; it carries over in Today's "Carried over" section
([`planning-views.md`](../08-features/planning-views.md)). The **triage queue** is
every open task that is late or stale and not acknowledged since its current
state began, excluding paused streams and lapsed routine occurrences. Its
actions are Defer (to a time, or to the next free slot), Already done
(backdated), Drop (with an optional reason) and Keep. Nothing is ever changed
automatically. [ADR-0047](../11-adr/0047-deadlines-and-lateness.md) is the
normative definition.

## State machine

```
   ┌──────┐    start     ┌──────────────┐    finish    ┌──────┐
   │ todo │ ───────────▶ │ in_progress  │ ───────────▶ │ done │
   └──────┘              └──────────────┘              └──────┘
      │  ▲                     │                          ▲
      │  │ unblock              │ (blocked_by added)      │ resurrect
      │  │                      ▼                          │
      │  │              ┌────────────┐                    │
      │  └──────────────│  blocked   │────────────────────┘
      │                 └────────────┘
      │
      ▼
  ┌───────────┐
  │ cancelled │
  └───────────┘
```

- `done` and `cancelled` are *not* terminal: a task can transition back to
  `todo`. UI may warn but does not refuse.
- `blocked` is derived: a task is blocked iff **any** blocker in its effective
  dependency set (below) is not `done`/`cancelled`. A blocker this device has
  not yet materialized counts as open, so an op that names an unseen blocker
  converges without a repair pass. The persisted `state` is the user-set state;
  the UI shows the effective state.
- An unknown `state` value from a newer build reads as `todo` for every
  decision and is written back unchanged ([ADR-0044](../11-adr/0044-per-field-ops.md),
  [#321](https://github.com/justin13888/Sunrise/issues/321)).

### `blocked` across the offline boundary

`blocked` is never persisted. Each device computes it on read from the merged
`blocked_by` OR-set, after cycle resolution
([`scheduling-constraints.md` §Dependencies](./scheduling-constraints.md#dependencies)),
and the current state of the referenced blockers.

- A blocker completing on device B emits a `state` write. Device A, on
  applying it, recomputes `blocked` for every task that names it. There is no
  separate "unblock" op.
- A device offline while a blocker completes shows `blocked` until it syncs;
  the recomputation runs when the op is applied, and the UI updates without
  user action.

## Lifecycle

- **Captured** with no stream unless the capture names one (`#stream`) or the
  `capture_default_stream` preference is set. An unplaced, undated capture is
  in the Inbox.
- **Homed** by setting `stream_id` (drag, keyboard, or `#streamname` in
  capture), or explicitly left stream-less with `MarkTriaged`.
- **Planned** by setting `planned_at` (by hand, by defer, or by the planner),
  optionally bound to a Block.
- **Completed** by user action; `completed_at` set. For a routine occurrence,
  the streak counts the occurrence on the **first** transition to `done` inside
  the grace window, and a later `done → todo → done` is a no-op for the streak
  (see [`routines-and-recurrence.md`](./routines-and-recurrence.md)).
- **Resurrected** (`done` or `cancelled` back to `todo`) without restriction.
- **Deferred** by moving `planned_at` later; `deferred_count` gains 1, and the
  UI shows the running count to nudge the user toward "drop it or do it".
- **Archived** to leave default views without deleting.
- **Deleted** sets `deleted = true`; the tombstone remains until compaction.
- **Restored** sets `deleted = false`. Edits made while the task was deleted
  are kept, and a restore shows them.

## Validation

Structural rules reject the write:

- `title` MUST be non-empty after trim.
- `priority` MUST be in 1..5; `estimated_duration_s` MUST fit in a `u32`.
- Each `stime` MUST be well-formed, and a `zoned` value's `tz` MUST be an IANA
  name the bundled tzdb resolves at write time.
- `completed_at` MUST NOT be after now, and MUST NOT be before `created_at`.
- `blocked_by` MUST NOT contain the task's own id.
- A `blocked_by` addition that would close a cycle in this device's current
  graph is rejected at submit. A cycle formed concurrently on two devices is
  resolved deterministically at read time, not rejected
  ([`scheduling-constraints.md` §Dependencies](./scheduling-constraints.md#dependencies)).
- Planning a task at a time that violates a `hard` time constraint (time of day,
  day of week, date range) in the reader's zone is rejected by every write path:
  ordinary submit, triage and `plan_commit` alike. `plan_preview` reports it as
  Blocking. An `at_place` requirement never rejects a write
  ([ADR-0051](../11-adr/0051-places.md)).
- A Task's serialized envelope (encrypted) MUST NOT exceed **1.25 MiB**.
  Over-limit submits return `VALIDATION_PAYLOAD_TOO_LARGE`, and the UI offers a
  one-click conversion of the body into an Attachment.

Ordering expectations **warn** and never reject, because concurrent per-field
edits can produce any combination and a rule merge cannot enforce must not be
one a command pretends to ([ADR-0047](../11-adr/0047-deadlines-and-lateness.md) §1):

- `target_at ≤ hard_due_at`, and `planned_at ≤ hard_due_at`, compared by
  resolving both in the reader's zone ([`time.md` §2](../10-cross-cutting/time.md#2-comparisons-resolve-through-the-readers-zone-never-through-index_ms)),
  never on the storage index key.

## Merge mapping

Per [ADR-0044](../11-adr/0044-per-field-ops.md):

| Field | Merge |
|---|---|
| scalars (`title`, `state`, `priority`, `energy`, `stream_id`, the three times, `completed_at`, `cancel_reason`, `sort_order`, `triaged_at`, `late_acknowledged_at`, …) | per-field LWW register on `(hlc, device_id, seq)` |
| `contexts`, `blocked_by` | add/remove OR-sets |
| `blocks` | derived from `block_tasks`, not merged on the Task |
| `deferred_count` | PN-counter |
| `scheduling_constraints` | one register for the whole list ([`scheduling-constraints.md`](./scheduling-constraints.md)) |
| `body` | opaque bytes, one register |

## Status in the tree

The fields above are the design of record. The tree still ships the previous
shape, and each gap is tracked:

- `stream_id` is required, and "no stream" is the Inbox sentinel stream
  (`crates/sunrise-domain/src/task.rs#Task`,
  `crates/sunrise-domain/src/inbox.rs`): [#332](https://github.com/justin13888/Sunrise/issues/332).
- The two times are `scheduled_at` and `due_at`; `DeferTask` takes epoch
  milliseconds, skips `validate_invariants` and writes an `Instant`
  (`crates/sunrise-core/src/engine/task.rs#defer_task`); `completed_at` can only
  be "now": [#334](https://github.com/justin13888/Sunrise/issues/334), [#335](https://github.com/justin13888/Sunrise/issues/335).
- The whole Task merges as one full-state LWW unit, so `contexts`, `blocked_by`
  and `deferred_count` lose concurrent edits: [#319](https://github.com/justin13888/Sunrise/issues/319).
- The `due ≥ scheduled` check compares storage index keys: [#336](https://github.com/justin13888/Sunrise/issues/336).
- Concurrent `blocked_by` cycles persist: [#333](https://github.com/justin13888/Sunrise/issues/333).
- A delete cannot be undone: the client's undo refuses it
  (`crates/sunrise-client-core/src/undo.rs`), because a legacy full-state
  tombstone has no restore op: [#319](https://github.com/justin13888/Sunrise/issues/319).
- Manual order lives in the Apple client's `UserDefaults`, not in `sort_order`:
  [#340](https://github.com/justin13888/Sunrise/issues/340).
- `routine_occurrence` is an instant, not the civil key: [#331](https://github.com/justin13888/Sunrise/issues/331).
